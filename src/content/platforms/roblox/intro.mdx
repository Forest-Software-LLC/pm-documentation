# Roblox

Roblox is Forest's original platform. Roblox packages are Luau modules: each installed package is a folder with a root module you require by its instance path.

If you're new to packages, start with [Concepts](/concepts/intro) for the platform-neutral ideas (what a package is, publishing, versioning, private access). This section covers the Roblox-specific mechanics layered on top.

<Callout type="info">
**Forest is not a Roblox Studio plugin.** You run the [Forest CLI](/forest-cli/install) from your project folder, and it installs packages as files next to your `forest.json`. Moving those files into the datamodel is your existing sync step, commonly [Rojo](https://rojo.space). Forest never edits your place file.
</Callout>

## What's specific to Roblox

- **Layout.** Packages install into a `Packages/` folder (next to your `forest.json` in a game project, or next to your root module when authoring a package), which *you* mount somewhere in the datamodel (commonly `ReplicatedStorage.Packages` via Rojo).
- **Importing.** You `require()` a package by its instance path. All requires inside the installed tree are relative, so the tree works wherever you mount it.
- **One entry point.** A package exposes a single root module whose return value is its entire public API.
- **Placement is the project's choice.** Packages don't declare a server or client realm. A project that wants server-only or dev-only packages puts them in their own [mount](/platforms/roblox/mounts), a second dependency folder in the same `forest.json`, and maps that folder where it belongs.
- **Aliases.** Two packages with the same name from different scopes can coexist by installing one under an alias.
