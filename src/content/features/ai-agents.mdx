# AI Agents & MCP

<PlatformBadges roblox uefn />

Connect your AI agent to Forest and it checks for a well-used package before writing code from scratch, reads its source and license, installs it, and publishes your own modules when you ask. Setup adds two things together: the **Forest MCP server**, which gives your agent the tools, and the **Forest skill**, which tells it when to use them.

### Sign in

Public packages work signed out, so you can skip this until you need your private packages or want to publish.

<Tabs items={['Claude Code', 'Claude app', 'Cursor', 'VS Code', 'Codex', 'Other agents']} storageKey="forest-agent">
  <Tabs.Tab>
    Run `/mcp`, pick **forest**, and choose **Authenticate**.
  </Tabs.Tab>
  <Tabs.Tab>
    Claude shows a **Connect** button in the chat the first time your agent needs your account.
  </Tabs.Tab>
  <Tabs.Tab>
    Cursor asks you to sign in to Forest the first time your agent needs your account. Follow its prompt.
  </Tabs.Tab>
  <Tabs.Tab>
    VS Code opens a browser to sign in the first time your agent needs your account.
  </Tabs.Tab>
  <Tabs.Tab>
    Run in your terminal:

    ```bash
    codex mcp login forest
    ```
  </Tabs.Tab>
  <Tabs.Tab>
    Your agent starts the sign-in the first time it needs your account, usually by opening a browser. Some have a command for it instead, like `/mcp auth forest` in Gemini CLI.
  </Tabs.Tab>
</Tabs>

A forest.dev page shows which app is asking, the account it will act as, and the permissions it wants. Approve, and you're connected. Your agent still asks you before every publish.

## What your agent can do

- **Find packages:** search and browse the registry, including mirrored Wally packages.
- **Vet them:** read a package's README, files, and source, its versions and dependencies, and its license rating with caveats.
- **Install them:** it gives you the `forest install` command, or runs it for you if your agent can use a terminal.
- **Work with your account:** list your packages and your Studios' packages, private ones included.
- **Publish:** send a package's files to Forest for you, after you approve. Text files only, up to 200 files and 1 MB, at most 10 publishes an hour; packages with `.rbxm` models are published with the [forest CLI](/features/publishing).

Every app you've signed in with is listed under **Connected apps** in your forest.dev profile settings, where **Disconnect** cuts it off immediately.

<Callout type="warning">
Package READMEs and source are written by their authors. Your agent treats that text as data, not instructions, and never publishes because some package text told it to.
</Callout>

## In CI and scripts

Agents that run without a person present can skip sign-in and send a Forest [API token](/features/ci) instead. API tokens are read only: they reach private packages but can't publish. In Claude Code:

```bash
claude mcp add --transport http forest https://api.forest.dev/mcp --header "Authorization: Bearer $FOREST_TOKEN"
```

Your shell fills in `$FOREST_TOKEN`, and Claude Code stores the token outside your repository. For a project `.mcp.json` you commit, reference the variable instead so the token never lands in the file:

```json
{
  "mcpServers": {
    "forest": {
      "type": "http",
      "url": "https://api.forest.dev/mcp",
      "headers": { "Authorization": "Bearer ${FOREST_TOKEN}" }
    }
  }
}
```

## Agents without MCP

An assistant that can only fetch URLs can use Forest's public HTTP API instead. Paste `https://forest.dev/llms.txt` into the chat and ask it to read it: that file documents every endpoint.
