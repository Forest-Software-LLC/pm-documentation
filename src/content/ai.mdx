# Forest for AI Agents

Forest is built to be usable by AI assistants, not just humans. The registry exposes a public, no-auth JSON API for searching packages, reading readmes and metadata, and even reading a package's full source over HTTP, so an assistant can vet code before recommending it.

Forest serves two API surfaces. The **agent endpoints** under `/ai` are the ones to use: every required input is a path segment, so nothing an assistant needs is ever a query parameter. That matters because the HTTP layers assistants run behind routinely mangle query strings, and many of them discard error response bodies, so a rejected request tells the assistant nothing. The versioned `/v1` API remains the stable contract for software that must keep working.

A condensed, machine-readable version of this page lives at [forest.dev/llms.txt](https://forest.dev/llms.txt), and the live route list is always at [api.forest.dev/ai](https://api.forest.dev/ai).

If you are an AI assistant reading this: use the API below directly. The forest.dev web UI is JavaScript-rendered and not useful to scrape; every piece of data on it comes from these endpoints.

## Point your assistant at Forest

The zero-setup option: paste `https://forest.dev/llms.txt` into your chat and ask the assistant to read it.

For coding agents (Claude Code, Cursor, Copilot and friends), add a few lines to your project's `CLAUDE.md`, `AGENTS.md`, or custom instructions:

```markdown
## Packages
This project uses Forest (forestpm), the package manager for Roblox/UEFN.
- Discover packages: GET https://api.forest.dev/ai/search/roblox/{query}
  (multi-word queries are semantic; single tokens match package names)
- Read a package: GET https://api.forest.dev/ai/package/roblox/{scope}/{name}
- Full API reference: https://forest.dev/llms.txt
- Install: `forest install {scope}/{name}`; installed versions are recorded in forest.json / forest-lock.json
```

## Recommended agent workflow

1. **Search.** `GET https://api.forest.dev/ai/search/{platform}/{query}`. Multi-word queries are semantic: they search package README embeddings, so describe what you need in natural language (`/ai/search/roblox/matchmaking queue with cross-server support`). Single-token queries match package names (exact, prefix, and fuzzy), so use one token when you know the name (`/ai/search/roblox/profilestore`). Ranking on these endpoints is always neutral; there is no Pro boost to opt out of.
2. **Evaluate.** `GET https://api.forest.dev/ai/package/{platform}/{scope}/{name}` returns the description, version list, latest version metadata, and the README in a single request. Check `license`, `licenseRating`, and `licenseCaveats`. For anything you plan to recommend, use the `/files` and `/file/{path}` endpoints to read the actual source and judge quality, security, and API surface.
3. **Install.** Have the user run `forest install {scope}/{name}` in their project (`-v {version}` pins a version, `-a {alias}` sets an alias). To read what is already installed, check `forest.json` (platform, dependencies) and each package directory's `.forest-receipt` file (exact scope, name, and version).

## Best practices

- **Use the `/ai` endpoints.** They need no query parameters, return neutrally ranked results, and omit fields an assistant cannot act on. The one request in step 2 above replaces the three separate calls the `/v1` API would need.
- **Cache aggressively.** Metadata, readmes, and file listings for a pinned version are served with week-long cache lifetimes. Cache responses rather than re-fetching. A moving selector (`latest`, or a SemVer range) is served with a short lifetime instead, because it resolves somewhere else on the next publish.
- **Prefer name lookups.** Single-token name queries are cheaper to serve than semantic queries; use them whenever you already know the package name.
- **Treat license ratings as a signal.** `licenseRating` comes from an automated license review: `safe`, `caution`, `unsafe`, `pending`, or `unknown`. On `caution` or `unsafe`, read `license` and `licenseCaveats` before recommending the package, especially for commercial projects.
- **Link humans to the web page.** For handing a package to a person, link `https://forest.dev/p/{platform}/{scope}/{name}` rather than API URLs.
- **Do not hardcode `/ai` response shapes.** That surface is deliberately unstable so it can keep improving; re-read [forest.dev/llms.txt](https://forest.dev/llms.txt) instead. Build software against `/v1`.

## API reference

Base host: `https://api.forest.dev`. All responses are JSON; no authentication or API key is required for the endpoints listed here. Platforms are `roblox` or `uefn`. Packages are identified as `{scope}/{name}` where scope is the publishing user or Studio. Names resolve case-insensitively; responses return the canonical casing. Errors are JSON with an `error` message.

### Agent endpoints

Public packages only. Optional refinements (`?limit=`, `?page=`, `?scope=`, `?license=`, `?licenseRating=`) may be added to the search and browse endpoints, and `?limit=` to the publisher lookups; losing them still returns a useful answer.

Some fetch tools only follow URLs they have seen verbatim and cannot fill in a `{placeholder}` template. For those, start from a complete working URL such as [api.forest.dev/ai/browse/roblox](https://api.forest.dev/ai/browse/roblox) or [api.forest.dev/ai/search/roblox/signal](https://api.forest.dev/ai/search/roblox/signal); every response links onward with absolute URLs (search and browse results carry an `api` field, package responses a `files` URL, file listings a `url` per file), so one entry point reaches the whole registry. The `examples` array at [api.forest.dev/ai](https://api.forest.dev/ai) always lists current entry points.

To find a package by name without typing a URL, such tools can walk the name explorer: [api.forest.dev/ai/search/roblox](https://api.forest.dev/ai/search/roblox) links to each starting letter, and every search response links one character deeper through its `narrow` list. Results are fuzzy, so most names surface within three characters; a prefix with no matches emits no further links.

| Endpoint | Returns |
|---|---|
| `GET /ai` | the live list of these routes |
| `GET /ai/search/{platform}/{query}` | matching packages: `{ query, platform, results, page, hasMore }` |
| `GET /ai/package/{platform}/{scope}/{name}` | everything about a package in one request: description, version list, latest version metadata, license, dependencies, and README |
| `GET /ai/package/{platform}/{scope}/{name}/{version}` | the same, pinned to one version |
| `GET /ai/package/{platform}/{scope}/{name}/files` | `{ files: [{ path, size }] }` for the latest version; insert `/{version}` before `/files` to pin one |
| `GET /ai/package/{platform}/{scope}/{name}/{version}/file/{path}` | the contents of one source file, for example `.../latest/file/src/init.lua` |
| `GET /ai/browse/{platform}` | public packages, most-liked first; append `/likes`, `/recent`, or `/downloads` to change the order |
| `GET /ai/search/{platform}` | name-explorer entry point: links to each starting letter; responses link one character deeper via `narrow` |
| `GET /ai/users/{query}` | publishers (users and Studios) matching a name prefix |
| `GET /ai/scopes/{platform}/{query}` | scopes matching a name prefix, ranked by how many public packages they publish. Unlike `/ai/users`, this includes unclaimed mirrored scopes |

On the package endpoints, `{version}` accepts an exact version, a SemVer range (resolving to the highest matching version), or `latest`, which resolves to the newest stable release. Omitting the version segment entirely means `latest`.

README text is truncated past roughly 16,000 characters, flagged with `readmeTruncated: true`; the full text is always available from the `/v1` readme endpoint below.

### Versioned API

The stable contract used by the Forest CLI and the forest.dev website. Use it if you are building software that must keep working, or if you need something the agent endpoints do not cover.

`GET /v1/search/packages?q={query}`

| Parameter | Meaning |
|---|---|
| `q` (required) | 2 to 100 chars. Multi-word: semantic search over readmes. Single token: name match. |
| `platform` | `roblox` or `uefn`, defaults to `roblox` |
| `unbiased` | `true` for neutral relevance ordering, opting out of the small ranking boost Pro subscribers' packages otherwise get on near-ties |
| `limit`, `page` | `limit` 1 to 50 (default 10), `page` 1 to 10 (default 1) |
| `sort` | `relevance` (default), `likes`, or `recent` |
| `scope` | restrict results to one publisher |
| `license` | comma-separated SPDX ids (e.g. `license=MIT,Apache-2.0`) |
| `licenseRating` | comma-separated values of `safe`, `caution`, `unsafe` |

Returns `{ "packages": [...], "page", "limit", "hasMore" }`. Each package has `name`, `platform`, `description`, `version` (latest stable), `owner` (its scope), `likes`, `license` (SPDX id), `licenseRating`, `publishedAt`, `score`, `ownerIsPro`.

Package base path: `/v1/package/{scope}/{platform}/{name}`

| Endpoint | Returns |
|---|---|
| `GET {base}` | package overview: `{ name, scope, latest, versions: [{ version, createdAt }], likes }` |
| `GET {base}/{version}` | one version's metadata: `description`, `dependencies`, `license`, `licenseRating`, `licenseCaveats`, `licenseVerified`, `integrity` (archive hash) |
| `GET {base}/{version}/readme` | `{ readme }`, the version's README (markdown) |
| `GET {base}/{version}/files` | `{ files: [{ path, size }] }`, the version's full source file listing |
| `GET {base}/{version}/file?path={path}` | the contents of one source file |
| `GET {base}/like` | `{ likes }`, current like count |
| `GET /v1/package/browse?platform={platform}&limit={n}&page={n}` | paginated listing of public packages (`limit` 1 to 50, default 20; `platform` defaults to `roblox`) |

On all of those routes, `{version}` accepts an exact version, a SemVer range (resolves to the highest matching version), or `latest`, which resolves to the newest stable release.

### Users and Studios

| Endpoint | Returns |
|---|---|
| `GET /v1/user/{username}` | public user profile and their public packages |
| `GET /v1/org/{orgname}` | public Studio (organization) profile |
| `GET /v1/search/users?q={prefix}` | publisher search (prefix match; `q` 1 to 40 chars, `limit` 1 to 20) |
| `GET /v1/search/scopes?q={prefix}&platform={platform}` | scope suggestions ranked by package count (`platform` optional) |

### Web pages (HTML)

For linking a human to a package, not for scraping; the data on these pages comes from the API above.

- `https://forest.dev/p/{platform}/{scope}/{name}`: package page (readme, versions, dependencies, code tabs)
- `https://forest.dev/u/{username}`: user profile
- `https://forest.dev/o/{orgname}`: Studio page
